1. Project Overview

Parkho (formerly CheckKaro) is an Indian consumer-facing web application that lets users look up ingredients in any packaged food or cosmetic product. Each ingredient is classified into one of four safety tiers, products are given an A–D grade, and all data is backed by FSSAI, WHO, and EU regulatory sources.

Core Value Proposition: Type any Indian product name (e.g. "Maggi 2-Minute Masala Noodles") and instantly see every ingredient explained in plain English — whether it's safe, questionable, or harmful — with regulatory context.

Request Flow

# User searches for "Maggi Masala Noodles"

1. React frontend → GET /api/product/search?name=Maggi+Masala+Noodles
2. Backend checks in-memory browse cache (2-min TTL)
3. If miss → multi-strategy search in Supabase (ai_extracted_products)
   - exact static_key match
   - exact name (ilike)
   - prefix match
   - word-by-word pattern match
   - substring match
4. Product found → classify each ingredient → compute A/B/C/D grade
5. Return ProductResponse JSON to frontend
6. Frontend caches result locally (10-min TTL)
7. React renders ingredient cards with classification badges

3. Database Structure (Supabase)

Supabase provides a hosted PostgreSQL database with built-in Auth and Storage. The project uses two Supabase clients:

  • supabase — public anon key, subject to Row Level Security (RLS)
  • supabase_admin — service role key, bypasses RLS for admin writes

Ingredient Classification System

Every ingredient is classified into one of four tiers, determined by matching ingredient names against keyword lists:

TierBadgeMeaningExample Ingredients
generally_recognisedSafeApproved by FSSAI, WHO, CODEX. No known significant concern.Water, Salt, Wheat Flour, Turmeric, Aloe Vera
worth_knowingWorth KnowingPermitted but worth being aware of. May cause sensitivity or have environmental concerns.MSG, Sugar, Palm Oil, Sucralose, Phenoxyethanol
commonly_questionedQuestionedSubject to regulatory bans in some countries, or linked to health concerns.Tartrazine (E102), Sodium Benzoate, Parabens, TBHQ, Titanium Dioxide
bannedBannedBanned or restricted in multiple major jurisdictions.Potassium Bromate, Triclosan, Azodicarbonamide, Sudan Red

A/B/C/D Grading System

GradeScore RangeMeaning
A85–100All or nearly all ingredients are generally recognised as safe. Best choice.
B70–84Mostly safe with a few worth-knowing ingredients. Good choice.
C50–69Has some commonly questioned ingredients. Use with awareness.
D0–49Multiple commonly questioned or banned ingredients. Reconsider.

Scoring: Start at 100. Each commonly_questioned ingredient −20 points. Each banned ingredient −40 points. Minimum 5.

Ingredient Database (ingredient_database.py)

A hand-curated Python dictionary with 672 entries. Each entry provides:

'sorbic acid': {
    'what_it_is':          'Natural preservative, also produced synthetically',
    'commonly_found_in':   'Cheese, baked goods, wine, fruit products',
    'one_line_note':       'GRAS by FDA; approved by FSSAI and EU',
    'regulatory_note':     'Permitted in India (FSSAI), EU (E200), USA (FDA)',
    'classification':      'generally_recognised',
    'health_effects':      'No known adverse effects at regulated levels',
    'countries_restricted': [],
    'fssai_position':      'Permitted preservative',
}

Entries are indexed by: common name, E-number (e.g. e200), INS number, and alternate spellings. The _normalize_ins() function converts "INS 200" → "E200" for unified lookup.

Key Patterns

Module-Level Cache (Result.jsx)

Product data is cached at module level (survives component re-mounts, shared across navigations). Cache has 10-minute TTL to match Render's 15-min idle window.

const _productCache = new Map()  // key → { data, ts }
const CACHE_TTL_MS = 10 * 60 * 1000

function cacheGet(key) {
  const entry = _productCache.get(key)
  if (!entry) return null
  if (Date.now() - entry.ts > CACHE_TTL_MS) { _productCache.delete(key); return null }
  return entry.data
}

Render Cold Start Retry

Backend on Render free tier sleeps after 15 min. First request after sleep can take 30–60s. Frontend retries once with extended timeout:

try { response = await tryBackend(10000) }
catch (firstErr) {
  if (firstErr.code === 'ECONNABORTED' || firstErr.code === 'ERR_NETWORK') {
    await new Promise(r => setTimeout(r, 2000))
    response = await tryBackend(25000)
  }
}

Client-Side Classification Overrides

Some ingredients are stored in Supabase with outdated classifications from old analysis runs. These are corrected client-side without touching the DB:

const CLASSIFICATION_OVERRIDES = [
  { pattern: /disodium\s+5['-]?\s*ribonucleotides/i, classification: 'worth_knowing' },
  { pattern: /tbhq|tertiary\s+butylhydroquinone/i, classification: 'commonly_questioned' },
  { pattern: /titanium\s+dioxide|\be171\b/i, classification: 'commonly_questioned' },
]

Supabase Multi-Strategy Search (Result.jsx)

When the backend is unavailable, the frontend falls back to querying Supabase directly using 5 progressively-broader search strategies:

// 1. Exact name   2. Prefix   3. Word pattern   4. Substring   5. Alphanumeric-only words
for (const fn of strategies) {
  const { data } = await fn()
  if (data && data.length > 0) return data[0]
}

New Developer Checklist

  1. Clone the repo & cd checkkaro
  2. Backend: cd backend && pip install -r requirements.txt
  3. Backend: Create .env with SUPABASE_URL, SUPABASE_ANON_KEY, SUPABASE_SERVICE_ROLE_KEY, ADMIN_EMAIL, GEMINI_API_KEY
  4. Backend: uvicorn main:app --reload → runs on localhost:8000
  5. Frontend: cd frontend && npm install
  6. Frontend: Create .env.local with VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY, VITE_API_BASE_URL=http://localhost:8000
  7. Frontend: npm run dev → runs on localhost:5173
  8. To add products: Use Admin dashboard at /admin (must be logged in as admin email)
